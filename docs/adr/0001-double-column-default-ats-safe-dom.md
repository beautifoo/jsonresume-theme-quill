# Double-column default with an ATS-safe document order

Five of the six sibling registry themes (pro, academic-cv-lite, data-driven, government-standard, and the single-column reading of most others) are single-column; only `reference` and `professional` use two columns. We decided **Quill defaults to the `double` layout** (main column + sidebar) because the two-column ratio is the theme's identity, while a `single` layout mode is available as a token for ATS-averse or formal contexts.

The ATS concern is addressed in the **implementation**, not the geometry: the DOM is one semantic flow (main sections first, sidebar after; real `section`/`h*`/`time` elements; no tables, floats, or positioned text; icons decorative). Modern parsers read document order, so both layouts — screen and print/PDF — parse in human reading order.

Considered: single-column default (rejected — would make Quill a quieter clone of `pro`); double built with tables/floats (rejected — that is what actually breaks parsers).

Consequences: verification of the layout × variant × scheme matrix is **manual** — the in-repo compare page (`bun run dev` → `/compare`) renders the full matrix (layout, scheme, variant, and locale at once, at full resolution), and the print target is checked through the standalone page's print dialog. An automated jsdom matrix was considered and rejected: jsdom never computes CSS, so the visual contract (floats, positioning, scale, page breaks) is invisible to it, and the manual matrix covers more dimensions than an automated one could. The `single` mode is exposed as a token: the `layout-single` / `layout-double` class on the resume root presets `--quill-cols-wide` (CSS cannot branch on a variable value, so the class is the selector form of the token); hosts switch layout by adding the class or overriding the token. Any future layout feature must preserve the flat document order.
